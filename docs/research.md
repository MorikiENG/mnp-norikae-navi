# 競合調査と技術選定

調査日：2026年10月19日。公開ページの構成・機能を調査し、デザイン・文章・料金データは転載していない。

## 参照した競合

- [価格.com 携帯料金シミュレーション](https://kakaku.com/keitai/simulation/)：利用条件に応じた比較、1年間の実質負担額、プラン一覧。表示される最大割引と実際に満たす条件を区別する必要がある。
- [楽天モバイル 料金シミュレーション](https://network.mobile.rakuten.co.jp/fee/simulation/)：現在の利用状況から自社プランへの差額を示す導線。複数ブランドを同じ式で比較する余地がある。
- [NTTドコモ 料金シミュレーション](https://www.docomo.ne.jp/charge/simulation/)：機種代や固定回線も含む条件設定。網羅性と入力負担のバランスが課題。
- [モバレコ](https://mobareco.jp/)：解説記事から比較・選び方へつなぐメディア型。大量のSEO記事を作らず、計算で誤解しやすい費用・特典に絞った解説を用意する。

上記は機能・導線の観察であり、料金の一次情報には使用しない。検索結果の掲載時期が古いものもあるため、他サイトの料金を最新料金として転用しない。

## 本サービスで採用する方針

現金支出とポイントを分け、初期費用・期限付き割引・予定改定を含む6/12/24か月を比較する。確認日と除外理由を表示する。ランキングは経済条件だけで並べ、広告報酬を受け取らないブランドも同じ計算式で扱う。

## 技術構成

- HTML/CSS/ブラウザ標準ES modules。フレームワークのランタイム・外部フォント・画像CDNは不要。
- Node.js 24の標準ライブラリによる静的ページ生成とテスト。
- Python 3標準ライブラリによる公式ページ取得・正規化・SHA-256変更検知。
- 料金・広告設定はJSON。料金の実行時API呼び出しやサーバー保存は不要。
- GitHub ActionsでCIと週次変更候補PRを作る。
- Cloudflare Pagesにdistを配信。Worker、DB、有料APIを使わない。

依存パッケージの更新作業を減らすこと、ブラウザ内で計算を完結すること、セキュリティと保守性を優先した。DOMへ渡す文字列をエスケープし、外部の取得HTMLは実行・配信しない。第三者スクリプトはCSPで拒否する。
